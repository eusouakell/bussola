# Bússola — art direction packet V1

**Run:** `bussola-public-case-v1`  
**Agent contract:** `editorial-art-director`  
**Inputs:** context packet + reference synthesis + narrative architecture + experience structure  
**Status:** representative proofs included; production page remains frozen.

## 1. Dominant visual idea

### **O que aparece / o que pesa**

The case is built around a recurring spatial contrast:

- **what appears on the surface** — balance, goal, interface, choice;
- **what sits underneath that decision** — revolving credit, financial context, architecture, evidence, limits.

This is not a decorative split-screen gimmick. It is the same tension that generated the product idea.

The visual world should feel like a **human/product case with evidence exposed**, not like a fintech campaign and not like an academic report.

## 2. Memory test

After closing the page, the reader should remember:

> **Fernando + a product surface + one sharp financial contradiction.**

Not:
- a red background;
- a serif;
- a card grid;
- a dashboard;
- a generic fintech phone mockup.

## 3. Core visual grammar

### 3.1 Human scale

Fernando and the team are not thumbnails.

- Fernando appears at near-human scale in the opening.
- Crop is deliberate; a full body/device is not required.
- The UI intersects his visual field rather than sitting in a separate column.
- The team later uses a documentary/contact-sheet rhythm, not a leadership directory.

### 3.2 Evidence lines

Financial/data and technical material use **alignment, rules, source rails and annotations** rather than cards.

A horizontal/vertical rule can separate:
- visible signal vs underlying pressure;
- user-facing layer vs system layer;
- Before vs After evidence.

Rules carry structure, not decoration.

### 3.3 Product surfaces are artifacts, not cards

When a rectangular surface appears, it should be because the artifact itself is rectangular:
- UI;
- architecture;
- source excerpt;
- prototype.

Do not wrap those artifacts in another rounded container.

### 3.4 Controlled overlap

Overlap is allowed only when it explains relationship:
- Fernando in front of/next to the UI;
- annotation touching the exact evidence it explains.

No stack of floating rectangles whose only purpose is depth.

## 4. Palette

### Base

- **Warm white:** `#FFFDFA`
- **Ink/navy:** `#172331`
- **Neutral rule:** `#D7D9D5`
- **Muted text:** `#59636E`

### Accent

- **Existing product orange:** `#BD4900`

Orange means:
- selected action;
- decision marker;
- annotation emphasis.

It does **not** become a campaign field.

### Explicitly excluded

- full-wall red;
- purple/blue AI gradients;
- startup green CTA system;
- sepia/paper texture as identity;
- dark/light section alternation as a substitute for composition.

## 5. Typography

### Display

Large grotesk/system sans, tight but not compressed:
- desktop hero: ~80–96 px depending on viewport;
- mobile: ~48–56 px;
- strong lowercase/diacritics;
- no serif as the main authorship device.

### Body

Neutral sans:
- desktop 18–20 px;
- mobile 16–18 px;
- generous line-height.

### Evidence / metadata

Monospace:
- 11–13 px;
- sources, states, reconstruction labels, commit/provenance metadata.

### Principle

The type system should support **scale contrast**:
- human/narrative = large sans;
- explanation = calm body;
- evidence = mono.

Do not create personality by adding another decorative font.

## 6. Hero

### Composition

- warm-white field;
- headline + short intro on the left;
- one composed scene on the right;
- Fernando overlaps a **cropped UI surface**, not a full phone mockup;
- UI can extend beyond its own visual boundary/crop;
- orange appears only inside the product state;
- provenance sits under the scene as metadata.

### Important

The hero does **not** contain the debt/rotativo insight. That belongs in Discovery.

### Mobile

- headline and intro first;
- scene below;
- UI intentionally cropped off the left/bottom edge;
- Fernando overlaps it;
- neither needs to be fully visible;
- one scene, not phone → person → caption as separate blocks.

## 7. Discovery

### Visual moment

The financial contradiction becomes a large evidence relationship:

**SALDO POSITIVO**  
— rule / source marker —  
**USO DO ROTATIVO**

The typography and rule make the relationship graspable before body copy.

Use:
- source note;
- “base sintética” label;
- one short interpretive sentence.

Do not:
- add a percentage;
- invent transactions;
- create a fake chart;
- use traffic-light colors.

## 8. Product decision

Use one continuous sequence:

`OBJETIVO → CONTEXTO → CENÁRIO → DECISÃO → CONSENTIMENTO`

No cards.

Each step can carry:
- one short verb/noun;
- one sentence max;
- a source/UI fragment when useful.

Orange marks the active/decision step, not every node.

## 9. Architecture / technical depth

The documented architecture itself becomes the artifact.

- wide;
- readable;
- source visible;
- selected annotations beside the relevant layer;
- allow open/full-size.

If a responsive redraw would change meaning, do **not** redraw. Provide a faithful image + accessible text summary/open-full behavior.

Dark ink may appear here as a **technical field**, but it should be earned by the artifact, not used as an alternating-section formula.

## 10. UX evolution

This is the craft centerpiece.

### Remove visual noise

- no decorative phone frames;
- no outer card panel;
- no equal-height dashboard tiles.

### Use

- large UI crops;
- one Before and one After surface;
- aligned task/state;
- annotation rail;
- one visible change per spread.

The eye should notice the content decision before it notices the framing.

### Mobile

Before → After in a clear vertical pair, with labels attached to each state.

No slider, flip or hidden comparison.

## 11. Prototype

Treat the prototype as a **lab bench**, not a conversion CTA.

- one large product area;
- explicit “simulação/PoC” context;
- open-full link;
- technical/source note nearby.

Avoid decorative browser chrome unless it helps orientation.

## 12. Team

Use a documentary contact-sheet logic:

- portraits at varied but controlled scale;
- visible names/contributions;
- no flip;
- no leadership-card grid;
- no equal “profile cards” with decorative borders.

If event/group photography becomes available with clear provenance, it can interrupt the portrait rhythm.

## 13. Colophon

Return to warm white/ink.

Use three large statements:
- observed;
- explored;
- refined later.

Then a compact source trail.

No campaign slogan and no dual CTA.

## 14. Motion

Motion is **not part of the identity**.

Allowed only after static approval:
- short coordinated entrance for Fernando + UI;
- state transition inside prototype;
- subtle reveal where it clarifies sequence.

No:
- infinite float;
- parallax required for depth;
- decorative text wipes;
- motion that hides/reveals essential evidence.

`prefers-reduced-motion` must preserve the complete final state.

## 15. Responsive rules

At 390/320px:

- crop before shrinking;
- reorder when needed, but preserve semantic pairs;
- preserve person + UI relationship;
- keep evidence labels attached;
- never force a full device into a narrow viewport merely to “show the phone”;
- keep monospace metadata secondary but readable;
- do not turn every desktop composition into a vertical stack of boxes.

## 16. Representative proofs

The accompanying proof sheet validates three moments:

1. **Hero:** Fernando + cropped UI as one scene.
2. **Discovery/Product decision:** evidence line + continuous decision sequence.
3. **UX evolution:** large UI surfaces + annotation rail, without phone/card framing.

These are **art-direction proofs**, not production markup.

## 17. Rejection checklist

Reject the route if it becomes:

- generic fintech landing page;
- generic portfolio template;
- serif + warm white = “editorial”;
- card grid;
- full-wall impact color;
- tiny phone mockups;
- UI buried inside a device frame;
- corporate team directory;
- animated before it is composed;
- desktop simply stacked at mobile.
